# 工程師工作上傳與挑選規格

狀態：草稿，2026-10-26。詞彙以 [CONTEXT.md](../CONTEXT.md) 為準；決定理由見 [ADR 0004](adr/0004-single-workid-binding-with-auto-sync.md)。取代 [簡化週報規格](simplified-weekly-report-spec.md) 與票據 `weekly-report-simplified-impl/issues/08-source-link-picker.md` 中關於來源連結的規則（只挑頂層、子項不單獨挑、資料放伺服器目錄、摘要必填、一任務多筆佐證、手動輸入 `workId`）。

## Problem Statement

課長寫週報時，要從工程師本週工作中找出值得向部級報告的項目，現在只能在另一個 HTML 工具標註，再回週報網站手寫內容，且網站只能把頂層工作掛成佐證。已進週報的項目每週要手動對照工程師進度，看不出本週變動多少。

## Solution

課長先把所屬課別的工程師工作彙整 JSON 上傳到週報網站，在新的「工程師進度」頁檢視、標註重要工作並寫 comment。接著在專案、重大系統異常、系統維護與營運、人力與組織異動、新技術評估各頁籤挑選這些工作新增項目；項目以工作編號綁定，已存在的項目則在重傳彙整後自動更新進度，並顯示進度變動（+xx%）。

## User Stories

1. 身為課長，我想上傳本週所屬課別的工程師工作 JSON，以便不必手動重打工作內容。
2. 身為課長，我想系統由檔名日期決定週次，以便不會把檔案傳到錯的週。
3. 身為課長，我想上傳到別課的檔案被拒絕並說明原因，以便避免污染他課資料。
4. 身為課長，我想非 JSON、缺必要欄位或檔名不符慣例的檔案被拒絕並顯示原因，以便知道如何修正。
5. 身為課長，我想比現有資料更舊週次的檔案被拒絕，以便舊檔不會蓋掉新資料。
6. 身為課長，我想同一週重傳時以工作編號合併並保留我的標註與綁定，以便補傳不會丟工作。
7. 身為課長，我想新檔沒有的工作仍保留最後狀態，並看到「本週彙整未出現此工作（可能本週無進度）」，以便不誤判為異常。
8. 身為課長，我想在「工程師進度」頁看到依工程師分組的多層工作樹，以便瀏覽全課工作。
9. 身為課長，我想看到工時總覽、耗時 ≥10H 標示與 RMS 標記，以便快速抓重點。
10. 身為課長，我想標註重要工作並寫 comment，以便作為部級報告素材。
11. 身為課長，我想只看重要工作，以便專注在候選。
12. 身為課長，我想上傳檔已帶的重要與 comment 自動匯入，以便沿用 HTML 工具的成果。
13. 身為課長，我想看到同一工作上週的 comment 作為參考，以便延續判斷。
14. 身為課長，我想已綁定項目在列表上標示「已綁定」，以便不重複挑選。
15. 身為課長，我想一個工作編號只能綁一個項目，以便進度來源唯一。
16. 身為課長，我想挑選任一層級的工作，並看到該工作與下一層子工作，以便挑到粒度適當的項目。
17. 身為課長，我想父工作與子工作各自綁定不同項目，以便分頁籤呈現。
18. 身為課長，我想在非專案頁籤挑工作新增項目，標題預填工作內容、內容預填我的 comment，以便只補影響與下一步。
19. 身為課長，我想挑工作建立專案的關鍵任務時先選專案與階段，名稱與負責人預填，以便少打字。
20. 身為課長，我想計畫日期只取工程師的計畫起迄、缺值時由我填，以便不被大項截止日誤導。
21. 身為課長，我想專案任務只顯示被選的那一項而不顯示子工作，並以工作編號追蹤，以便專案時程保持簡潔。
22. 身為課長，我想重傳彙整後已綁定項目的進度自動更新，以便不必逐項對照。
23. 身為課長，我想關鍵任務的狀態依工程師狀態自動對應（已完成→完成；處理中、簽核中、待發佈→進行中；待執行→開放），以便狀態與工作一致。
24. 身為課長，我想工程師標示「中止」時只收到提示而不自動取消，以便由我決定並寫理由，避免破壞依賴鏈。
25. 身為課長，我想工程師標示「已完成」時自動設為完成並標示「缺實際結束日」，以便我補日期。
26. 身為課長，我想自動變更的項目顯示徽章與原狀態及原進度，以便知道哪裡變了。
27. 身為課長，我想逐項確認徽章，並在頁籤上看到未確認數量，以便不遺漏。
28. 身為課長，我想一鍵還原為原狀態，且還原後該次上傳不再自動覆寫，以便否決不合理的更新。
29. 身為課長，我想手動覆寫進度後自動同步暫停並顯示工程師最新進度差異，以便我的判斷不被悄悄蓋掉。
30. 身為課長，我想按「改回跟隨工程師」恢復同步，以便需要時回到自動。
31. 身為課長，我想看到項目的進度變動（+xx%、負值照顯示、首次「新增」），以便向部級說明本週進展。
32. 身為部級主管，我想唯讀檢視三課的工程師進度頁與標註，以便掌握素材全貌。
33. 身為部級主管，我想正式週報文件顯示進度變動與自動產生的附錄（所有已綁定項目的編號、內容、進度、變動），以便不需另行彙整。
34. 身為部級主管，我想課長的重要旗標與 comment 不出現在正式文件，以便內部素材不外流。
35. 身為課長，我想建立下週時已綁定項目延續、重要標註不延續，以便每週重新篩選。
36. 身為課長，我想他課課長看不到我課的工程師進度，以便權限單純。

## Implementation Decisions

- **上傳與儲存**：課長上傳所屬課別檔案，後端驗證後以服務帳號寫入資料 repo 該週資料夾並 commit，與課別草稿相同的 git 寫入流程。工程師彙整不再放伺服器設定目錄，舊的唯讀讀取端點由新端點取代。
- **週次**：由檔名 `*_yyMMdd.json` 的日期推得，不讓課長手選。檔案 `target_section` 須等於登入課長所屬課別，否則拒絕。拒絕條件另含非 JSON、缺必要欄位、檔名不符、週次早於該課已有資料。
- **合併**：同週重傳以 `workId` 合併，保留標註與綁定；新檔缺漏的工作保留最後快照，僅提示。上傳檔內的 `isImportant`、`managerComment` 匯入為初始標註，之後以網站為準。
- **權限**：課長只可上傳、讀寫自己課；部級唯讀三課；課長之間互不可見。
- **標註**：重要旗標與 comment 只限當週，隨課別資料保存，不寫入發布文件，不延續到下週；下週以同一 `workId` 顯示上週 comment 供參考。
- **資料形狀**：非專案頁籤的項目與專案的關鍵任務各有一個 `workId` 欄位，全站唯一。關鍵任務原本的多筆 `evidenceLinks` 移除（系統尚未發布，無遷移）。來源連結摘要改為選填。項目另存最後同步的工程師進度、工程師狀態與待確認同步記錄（原狀態、原進度），以及進度是否由課長手動覆寫。
- **同步規則**：重傳後對已綁定項目更新進度為工程師 `percentage`；手動覆寫的項目暫停同步，只顯示差異提示，可改回跟隨。關鍵任務依對應表更新狀態；中止只提示；已完成設為完成且進度 100，實際結束日留空並標示缺漏。非專案項目沒有狀態欄，只顯示工程師狀態。每次自動變更產生待確認記錄，課長逐項確認或一鍵還原，還原後該次上傳不再自動覆寫。
- **進度變動**：本週同步後進度減去上週最後一個正式版中該項目記錄的進度；上週沒有該項目顯示「新增」。工程師檔的 `deltaPert` 不採用（資料中有負值與 `'?'`）。
- **多層選取**：樹可勾選任一層，畫面顯示被選工作與其下一層子工作；進度只取被選工作自己的 `percentage`，不彙總子工作。專案任務只顯示被選項。
- **預填**：非專案項目標題取工作內容、內容取 comment；關鍵任務名稱取工作內容、負責人取工程師姓名，計畫起迄只取 `planStartDate`/`planEndDate`，缺值必填，不用 `dueDate`。
- **工程師進度頁**：位於課別編輯導覽，與頁籤並列。保留工時總覽、多層樹、耗時標示、RMS 標記、重要與 comment、僅看重要；不含複製重要 ID 與下載更新 JSON。
- **發布文件**：項目旁顯示進度變動；附錄自動列出所有已綁定項目；標註與待確認記錄不出現。
- **模組**：新增一個前端純函式模組負責合併、狀態對應、進度變動、同步暫停與待確認記錄的計算；後端新增上傳端點與驗證；前端新增工程師進度頁及頁籤中的挑選介面。

## Testing Decisions

- 好測試只驗證外部行為：給定上週正式版、本週上傳與課長操作，輸出的項目進度、狀態、徽章與進度變動；不測內部結構。
- **純邏輯單元測試**（沿用 `tests/*.test.mjs` 風格，例如 `schedule-rules.test.mjs`）：合併、狀態對應含中止與已完成例外、進度變動（基準、新增、負值）、手動覆寫暫停與恢復、還原後不再覆寫、`deltaPert` 為 `'?'` 時不影響結果。
- **HTTP 煙霧測試**（擴充 `tests/smoke.mjs`）：課別不符、檔名不符、非 JSON、週次較舊被拒絕；合併寫入資料 repo 並 commit；部級唯讀三課；課長互不可見。
- **瀏覽器煙霧測試**（擴充 `tests/browser-smoke.mjs`）：只放一條主流程：上傳、標註並寫 comment、挑到專案建立關鍵任務、再上傳新檔、看到狀態徽章與 +xx%。
- 測試資料沿用 `tests/fixtures/engineer-work` 並補多層樣本；以 `temp/eng-works-data` 的 SEC1 結構為依據縮小。

## Out of Scope

- 工程師彙整的產生流程（由其他流程負責）。
- 工程師狀態新增欄位到非專案項目。
- 自動取消關鍵任務、自動填實際結束日。
- 跨課挑選與跨課課長互看。
- 彙整子工作進度到父工作。
- 沿用 HTML 工具的複製重要 ID、下載更新 JSON。
- 既有資料遷移（系統尚未發布）。

## Further Notes

- 範例資料：`temp/eng-works-data/CIM2_ENG_WeeklyReport_261022_SEC1.json` 與 `.html`。狀態共六種：已完成、處理中、待執行、簽核中、待發佈、中止；最深三層。
- 本規格取代簡化週報規格中的來源連結規則；實作後應更新該規格與 README 的對應段落。

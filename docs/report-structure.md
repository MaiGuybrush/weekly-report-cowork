# 處會週報架構與呈現設計

狀態：設計版，2026-09-26。配套系統設計見 [solution-design.md](solution-design.md)。本版以週四 13:30 處會為閱讀情境，強調本週變化、時程偏差與需要處級協助的事。

## 1. 正式報告目錄

| 順序 | 區塊 | 處會首先要看見的資訊 | 維護方式 |
| --- | --- | --- | --- |
| 0 | 本週管理摘要 | 重大成果、重要延期／風險／問題、需處級協調或決策 | Guy 統整；連回正文，不複製敘述 |
| 1 | 進行中專案進度 | 專案健康度、本週變化、下個里程碑、時程偏差與甘特圖 | 指定週報維護人更新，Guy 統整 |
| 2A | 系統維護與營運：重要新增需求 | 需求價值、影響、狀態、交付承諾 | 課長從工程師工作候選中選入 |
| 2B | 系統維護與營運：重大系統異常 | 影響、處置、恢復與永久改善 | 系統提示候選，課長決定是否重大 |
| 3 | 人力與組織異動 | 生效日期、職責交接、對工作的影響 | Guy 與相關課長編輯；按權限顯示 |
| 4 | 新技術評估 | 要解決的問題、評估證據、階段結論、下一步 | 評估中即可跨週追蹤 |
| 附錄 | 工程師工作明細與來源 | eCIM Work ID、來源連結、匯入時窗與完整度 | 系統整理，課長核對 |

報告頁首顯示處會日期、目前發布版號／時間，以及各課來源狀態。正文不直接倒入所有工程師工單；讀者可從項目展開來源。未結案項目跨週保留，同一事實只在一張主卡詳述。

## 2. 本週管理摘要

建議以短句呈現「本週成果」、「偏離計畫」、「需處級協助或決定」。每張摘要卡連到正文主項目，並標出負責人與下一期限。重要里程碑延期、專案轉為延遲／暫停、高影響風險或已發生問題、需處級協調／決策事項進入此區。Guy 可調整優先順序與語氣；未經他確認不自動發布。

## 3. 專案卡與甘特圖

### 處會摘要卡

每個專案先以一張可快速掃讀的卡片呈現：

1. 專案名稱、目標、實際專案負責人、週報維護人、參與課別／部門。
2. 健康度：正常／注意／延遲／暫停／完成，附一行理由。完成百分比可選填，不依工時推算。
3. 本週相對上週的成果與未達成事項；下個重要里程碑、目前預估日期及與計畫基準的差距。
4. 下週動作、負責人及期限；最重要的風險、問題、相依事項與待決策事項。

### 專案詳情

展開後顯示目標與交付成果、階段、重要里程碑、相關部門、eCIM 工作來源，以及四類管理紀錄：風險、已發生問題、跨部門相依、待決策事項。每筆管理紀錄至少有描述、影響、負責人、期限、狀態及本週更新。只有本週變化或需協調的內容進處會摘要，其餘仍可在詳情查閱。

### 甘特圖規則

- 甘特圖以**階段與重要里程碑**為行，顯示計畫基準、目前預估與實際完成；「今天／報告日」有明顯參考線。可看出延期天數與跨部門相依。
- 工程師 eCIM 工作在階段詳情以來源連結呈現，不逐筆畫成甘特長條。大型專案可折疊已完成階段；處會摘要先顯示接下來的關鍵階段與里程碑。
- 週報維護人可調整計畫基準及預估日期，不需 Guy 核准；每次基準變更記錄調整前後日期、原因、操作者與時間。甘特圖可檢視歷史基準。
- 甘特圖可點選項目開啟日期表單；修改時填原因，不直接拖曳長條改時程。原週報中的自由文字日期須經維護人確認後成為結構化日期。

## 4. 其他章節的項目卡

### 2A 重要新增需求

課級主管自行判斷哪些新增需求值得列入正文。目前可從本課工程師 eCIM 工作選入或手動新增；未來需求單 MCP 可提供本週新增需求候選。卡片記需求／系統名稱、提出單位、目的與影響、主責課、目前階段、交付日期、本週變化、下一步及來源 Work ID。未選入者只在來源池或附錄統計，不自動進正文。

### 2B 重大系統異常

系統可從工作內容提示疑似異常，是否列入由課長判斷。卡片記事件／系統、發生時間、影響範圍、處置、恢復時間與狀態、根因或待查項目、永久改善、負責人與期限。未知資訊顯示「待確認」及預計確認時間。系統恢復不等於改善結案；未完成改善持續追蹤。

### 3 人力與組織異動

每筆只記處會所需的生效日期、職責或系統交接、交接前後負責人、工作影響、下一步及期限。草稿只對 Guy 與相關課長可見；已發布內容僅有處會報告讀取權限者可見。避免記私人原因或與交接無關的個人資料。

### 4 新技術評估

評估中即可建立跨週項目。卡片記欲解決的問題、使用情境、候選方案、評估標準、本週證據、成本與限制、目前結論、下一個驗證動作及日期。結論為採用、續試或停止；如需處級決策，連到本週管理摘要。僅參加訓練或閱讀資料而無評估問題及下一步者，放在來源附錄。

## 5. 延續、結案與資料缺漏

各類項目保留穩定的跨週識別。下週建立草稿時沿用上週最新已發布版的未結案項目，顯示上週承諾與本週結果對照。課長確認結案後，本週保留一次結案摘要，下週退出正文但歷史可查。上週待決事項不能無聲消失，須記決策結果或新期限。

來源匯入失敗時顯示缺漏課別、人員及上次成功時間，不能顯示「本週無新增」或「本週無重大異常」。AI 或規則分類只標為建議，課長擁有正文入選決定權。

## 6. 編輯與正式頁面示意

```text
共同編輯器（章節導覽與來源側欄可收合）
┌──────────────┬────────────────────────────────┬──────────────┐
│ 章節／項目    │ 項目編輯；專案可切全寬甘特圖       │ 上週／來源差異 │
│ 可收合        │ 私人草稿狀態・儲存完成・完整預覽    │ 可收合        │
└──────────────┴────────────────────────────────┴──────────────┘

正式唯讀週報｜處會日期｜版號｜發布時間｜來源完整度
本週管理摘要 → 專案進度（摘要卡／展開甘特圖）
→ 系統維護（重要需求／重大異常）→ 人事異動
→ 新技術評估 → 工程師工作明細與來源附錄
```

預覽可關閉或全頁開啟，收起兩側欄後中央可接近全寬。正式頁固定連結指向指定發布版；重新發布取得新版本及新連結，舊版仍可查。正式頁適合投影與瀏覽器列印。

## 7. Prototype 檢視重點

設計文件完成後，以真實週報資料的記憶體複本做三種不同版面。Guy 檢查：實際文字長度下編輯區是否足夠、章節及預覽收合是否順手、專案甘特圖是否能看清日期差、週報投影與列印是否易讀，以及「私有草稿 → 儲存完成 → 預覽 → 發布新版」是否直觀。既有 JSON 沒有結構化甘特日期，Prototype 所補的排程資料必須標示為示意。

## 8. 不可變發布時程快照與修訂歷史（Publication Snapshot & Audit）

1. **一致性快照與狀態凍結**：
   - 每次 Guy 發布正式週報時，於單一交易中讀取並固化所有項目狀態、三種時程項目（階段 Phase、關鍵任務 Key Task、里程碑 Milestone）之穩定身分與起訖日期。
   - 同步固化發布當下評估之相依警示（前置衝突與搶先開始 active-warning）、外部交付提醒（已逾期 / 尚未交付），以及專案跨部門相依事項與其關聯。
   - 固化各項目於發布當下已發生的完整修訂歷史（包含操作人、時間、動作、必填原因、變更前後值）。
2. **版本隔離與不可變契約**：
   - 發布後的工作版編輯（改期、狀態調整、取消、移除相依連結或外部事項）絕不影響已發布版本所見內容與警示。
   - 發布讀者透過固定連結開啟指定版本，所見時程、警示與修訂歷史皆為凍結快照，伺服器時間推移亦不改變既有發布版的警示狀態。
   - 重新發布會產生全新版本號（Version 2, 3...）與新快照，舊版歷史永久可查且完全隔離。
3. **授權防護**：
   - 發布版讀取嚴格依據 `CanReadPublication` 檢查（Guy 或擁有 ReaderAccess 之授權帳號）。未授權訪問直接拒絕（403 Forbidden）。

## 9. 完整時程跨週延續（Weekly Schedule Continuation）

1. **從前週正式版建立獨立工作版**：
   - Guy 建立下週報告草稿時，系統由前週最新已發布版（Publication Snapshot）延續未結案專案，建立全新的獨立工作版本。
   - 延續完整時程圖，包含階段、關鍵任務與重要里程碑，以及進行中、已完成與已取消的所有項目。
   - 預設時程列表及甘特圖隱藏已取消項目，並在折疊區提供清晰追溯與重新啟用操作。
2. **穩定邏輯身分與歷史延續**：
   - 每一項時程項目在跨週具備穩定邏輯身分（Continuity ID），跨週追蹤與比對保持一致，同時具備新週自身的獨立實體 ID。
   - 時程項目於前週累積之所有修訂歷程（含操作人、時間、原因、前後值）及基準歷程完整延續至新週工作版，維護人可於時間軸彈窗無縫檢視完整脈絡。
3. **內部相依與外部事項關聯延續**：
   - 內部前置連結（Predecessor Links）自動重構並映射至新週對應的項目實體 ID，確保先後順序與警示延續，且不引用前週可變資料。
   - 跨部門相依事項（External Dependencies）與關聯連結、外部修訂歷程完整延續至新週，逾期提醒與交付狀態持續受控。
4. **雙向版本隔離**：
   - 新週建立後，前週工作版之後續修改或再次重新發布（如產生 Version 2, 3），絕不靜默影響已建立之新週。
   - 新週工作版之任何時程編修、取消或新增相依，亦完全不影響前週之任何已發布正式快照及前週工作資料。

## 10. 重新設計專案甘特圖元件與處會摘要（Redesigned Gantt & Summary）

1. **三種時程項目之精確呈現**：
   - **專案階段 (Phase)** 與 **關鍵任務 (Key Task)**：呈現為期間條（Period Bars），清楚展示有效原始計畫基準（Baseline Bar）、目前目標（Forecast Bar）及實際結果（Actual Bar）。
   - **重要里程碑 (Milestone)**：永遠呈現為單日點標記（Point Markers），決不跨越期間。待達成里程碑以最新目標日為主要鑽石標記（藍鑽/金鑽），並在原始目標不同時提供幽靈參考點；已達成里程碑以實際達成日為主要翡翠實心鑽石標記，最新目標日亦可查。不以實際日期推測完成狀態。
2. **處會摘要與按需展開關鍵任務**：
   - 甘特圖預設聚焦於階段與重要里程碑，讓處會主管先快速掌握全局交付進度。
   - 專案詳情與甘特圖提供「展開關鍵任務」開關與各階段獨立展開切換，按需展開隸屬該階段之關鍵任務與專案直屬任務，清晰呈現具體工作期間、負責人及進度。
   - 已取消項目預設隱藏，並具備明確入口開關（「顯示已取消項目」）可展開檢視，保留承諾歷史且以刪除線與取消標籤標示，不因取消或實際日期推測完成。
3. **指標、警示與規範化表單入口（禁止拖曳直接改動承諾）**：
   - 每一時程列清晰顯示有效原始計畫、目前計畫或實際結果、總偏差（如 `+3 天`、`提前 2 天` 或 `如期`）、項目狀態及內外部相依警示（⚠️ 前置順序衝突/未完成警示、外部交付提醒）。
   - 嚴格禁止以滑鼠拖曳方式直接修改日期承諾。點擊甘特圖列直接進入規範表單，每一次改期皆需填寫理由、走版本安全租約並留下不可竄改之修訂歷史。
4. **四個場景的一致性（Consistency Across Views）**：
   - **編輯預覽**、**固定發布頁**、**大螢幕投影**及**瀏覽器列印 / PDF 輸出**皆使用完全一致之時程語意與甘特圖呈現。
   - 列印時強制套用色彩保真（`print-color-adjust: exact`），軌道與點標記清晰輸出且防止分頁截斷。



## 11. 手動連結 eCIM 工作證據（Manual eCIM Evidence Links & Traceability）

1. **手動挑選與多來源關聯**：
   - 專案週報維護人可明確選取、增減關鍵任務（Key Task）的 eCIM 工作佐證；階段（Phase）與里程碑（Milestone）不允許連結具體工程師工作單。
   - 單一關鍵任務支援連結多筆 eCIM 來源工作；系統提供候選清單查詢（依當週已同步之 eCIM 來源）或手動輸入工作代碼，並要求填寫引用佐證原因。
   - 連結與解除連結均走租約樂觀鎖、專案版本遞增，並於時程項目的修訂歷程記載 `link-evidence` 與 `unlink-evidence`。
2. **eCIM 同步安全合約（嚴禁自動覆寫承諾）**：
   - eCIM 來源資料再次同步或重新整理時，**嚴格禁止**系統自動建立、改期、完成或取消關鍵任務，亦不得自動覆寫維護人的人工排程承諾。
   - 同步僅更新證據連結的最新狀態快照（`latest_payload`）；若來源內容相較於引用當時已變更，系統保留初始引用快照（`initial_payload`）並標記「來源變動（sourceChanged）」，維護人與讀者可展開雙欄比對查看內容差異。
3. **不可變發布快照與跨週穩定身分**：
   - 發布正式版時，所有連結之 eCIM 工作證據（含引用內容、當時最新狀態與理由）固化於不可變發布快照中，正式發布頁提供佐證清單與彈窗檢視。發布後的工作版修改與後續同步完全不影響已發布版本。
   - 建立新週報時，延續之關鍵任務保有穩定的 eCIM 工作身分（`work_id`），並於新週建立自己的獨立工作版連結，持續追蹤新週的來源最新狀態。

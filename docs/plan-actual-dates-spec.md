# 計畫／實際兩組日期規格

狀態：ready-for-agent，2026-10-12。依 [計畫／實際兩組日期](../.scratch/weekly-report-simplified/issues/08-plan-actual-two-dates.md) 的決策撰寫，補完 [簡化週報解決方案規格](simplified-weekly-report-spec.md) 之後剩餘的工作。詞彙以 [CONTEXT.md](../CONTEXT.md) 為準。

`weekly-report-simplified-impl` 地圖不再繼續：其票據 01–09 對應的功能已完成並提交，剩餘工作全部收斂於本規格。

## Problem Statement

階段、關鍵任務、里程碑目前各有原始、目前、實際三組日期。課長要維護的欄位太多，「更正原始計畫」與「一般改期」的區分也沒有意義：系統已移除應用內修訂紀錄與時程變更紀錄，歷史交給 git，區分原始與目前只剩操作負擔。甘特圖與偏差天數也因此要同時呈現三組日期。此外，舊的設計文件仍留在 repo 並被 `.scratch/` 引用，與現行規格互相矛盾。

## Solution

時程項目一律只有「計畫」與「實際」兩組日期。計畫是最新計畫，改期直接覆寫；實際是真正發生的日期。偏差天數為實際相對於計畫。甘特圖每列顯示計畫條（淺）與實際條（深），里程碑顯示計畫鑽石與實際鑽石。舊設計文件刪除，規格與實作計畫更新為兩組日期的描述。

## User Stories

1. 身為課長，我想為階段只填計畫起迄與實際起迄，以便不必判斷什麼是原始、什麼是目前。
2. 身為課長，我想為關鍵任務只填計畫起迄與實際起迄，以便維護的欄位更少。
3. 身為課長，我想為重要里程碑只填計畫日期與實際日期，以便里程碑與其他項目一致。
4. 身為課長，我想直接修改計畫日期來改期，以便不必先選「更正」或「改期」。
5. 身為課長，我想在項目尚未開始時把實際日期留白，以便畫面清楚顯示尚未發生。
6. 身為課長，我想在項目完成時填入實際結束日期，以便偏差天數自動算出。
7. 身為課長，我想在表單上看到「計畫」與「實際」兩個明確標籤，以便不必記得欄位名稱。
8. 身為課長，我想看到實際相對於計畫的偏差天數，以便知道延誤多少。
9. 身為課長，我想在項目未完成時偏差天數顯示「—」，以便不會誤讀為零延誤。
10. 身為課長，我想在里程碑未達成時偏差天數顯示「—」，以便與未完成的項目一致。
11. 身為課長，我想在甘特圖每列同時看到淺色計畫條與深色實際條，以便一眼比較計畫與實際。
12. 身為課長，我想在甘特圖看到里程碑的計畫鑽石與實際鑽石，以便比較達成情形。
13. 身為課長，我想甘特圖不再顯示「原始目標」幽靈點，以便畫面更簡潔。
14. 身為課長，我想前置項目的實際日期優先於計畫日期參與相依檢查，以便已發生的事實決定警示。
15. 身為課長，我想相依檢查在沒有實際日期時使用計畫日期，以便尚未開始的項目仍能被檢查。
16. 身為課長，我想順序衝突警示與「前置未完成但後續已開始」警示的行為與現在相同，以便改版不改變我熟悉的警示。
17. 身為課長，我想儲存後的 JSON 只含 `plan*` 與 `actual*` 欄位，以便 git diff 一眼看出改了哪個日期。
18. 身為課長，我想用 git 歷史追溯計畫曾經如何改動，以便不需要應用內的變更紀錄。
19. 身為部級主管，我想在正式版頁的甘特圖看到計畫條與實際條，以便對外呈現計畫與實績。
20. 身為部級主管，我想舊版週報快照在畫面上不報錯，以便歷史版本仍可開啟（新舊欄位不並存，舊欄位直接忽略）。
21. 身為維護者，我想 repo 內不再有互相矛盾的舊設計文件，以便新成員只讀到現行規格。
22. 身為維護者，我想 `.scratch/` 內沒有指向已刪除文件的連結，以便文件導覽不會失效。
23. 身為維護者，我想簡化週報規格與實作計畫描述兩組日期，以便文件與程式一致。
24. 身為維護者，我想自動化測試覆蓋新日期優先序、偏差天數與甘特圖模型，以便日後改動不會悄悄破壞行為。
25. 身為維護者，我想瀏覽器煙霧測試涵蓋編輯計畫與實際日期、儲存、重新載入後甘特圖顯示兩條，以便端到端行為有保障。

## Implementation Decisions

- **資料欄位：** 階段與關鍵任務使用計畫起、計畫迄、實際起、實際迄；里程碑使用計畫日期與實際日期。「計畫」為最新計畫，改期直接覆寫。舊的原始與預測欄位從型別、表單、規則、甘特圖模型中完全移除。
- **舊資料：** 不遷移，不保留相容層。舊欄位若出現在既有 JSON 中一律忽略（尚未發布，repo 內無真實資料）。
- **日期優先序：** 相依檢查與警示取日期時由「實際，否則預測，否則原始」改為「實際，否則計畫」；警示語意與文字不變。
- **偏差天數：** 定義為實際相對於計畫。單日項目比較日期；區間項目比較結束日期。尚無實際結束日期或里程碑未達成時顯示「—」。
- **甘特圖模型：** 每列輸出計畫條與實際條（實際可缺）；里程碑輸出計畫鑽石與實際鑽石（實際可缺）。移除原始目標幽靈點相關輸出。顯示模型仍是純函式，與元件分離。
- **甘特圖元件：** 計畫條使用淺色、實際條使用深色，疊在同一列；圖例更新為「計畫」與「實際」；既有互動（展開收合、顯示已取消、今日線、tooltip、📎/⚠/🌐）不變。tooltip 顯示計畫、實際與偏差天數。
- **專案時程編輯面板：** 日期欄位只有「計畫」與「實際」兩組；移除「更正原始計畫」與「一般改期」的區分及其相關文案。
- **後端：** 不變。後端不理解時程語意，只驗證擁有權、路徑與 JSON 形狀。
- **文件：** 刪除 `solution-design.md`、`report-structure.md`、`implementation-spec.md`、`implementation-plan.md`、`project-schedule-redesign-spec.md`；清除 `.scratch/` 內所有指向它們的連結（含舊地圖與舊票據中的引用，改為純文字註記「已刪除」或直接移除該句）；`docs/agents/issue-tracker.md` 內對 `project-schedule-redesign-spec.md` 的連結同步處理；更新簡化週報規格與實作計畫的日期描述，並移除其中「取代舊文件」的待辦語句，改為「已取代並刪除」。
- **詞彙：** `CONTEXT.md` 的「原始計畫」「目前計畫」若仍存在則改為「計畫」「實際」，並移除「更正原始計畫」相關詞條。
- **實作票據收尾：** 將 `weekly-report-simplified-impl` 票據 04 內「原始計畫、目前計畫」的敘述改為兩組日期，並把已完成票據的核取方塊補勾，之後不再新增該系列票據。

## Testing Decisions

- **好測試的標準：** 只驗證外部可觀察行為（輸入時程項目，輸出警示、偏差天數、顯示模型、畫面上的條與鑽石），不測內部資料結構或私有函式。
- **Seam 一：時程規則自檢。** 擴充現有的 node 規則測試，涵蓋：日期優先序為實際否則計畫；有實際日期時警示依實際判斷；偏差天數（延誤、提前、準時、未完成為「—」）；既有循環、跨專案、順序衝突、即時警示、外部交付逾期、取消與重新啟用案例在新欄位下仍通過。
- **Seam 二：甘特圖模型測試。** 擴充現有的 node 模型測試，涵蓋：有計畫無實際時只輸出計畫條；有實際時輸出兩條；里程碑計畫鑽石與實際鑽石；不再輸出原始目標點；已取消項目與展開收合維持原行為。
- **Seam 三：瀏覽器煙霧測試。** 改寫現有流程：課長編輯一個含階段、任務、里程碑的專案的計畫與實際日期並儲存，重新載入後甘特圖顯示計畫條與實際條，偏差天數正確；部級發布後正式版頁同樣顯示兩條。
- HTTP 煙霧測試不新增 seam：後端不理解日期，現有測試維持通過即可。
- **既有範例：** 規則與模型的 node assert 測試、瀏覽器煙霧測試皆已在 repo 中，沿用其寫法與執行方式。
- 每個步驟結束時後端建置、前端建置、全部測試皆須通過。

# 工程師進度頁重新設計規格

狀態：草稿，2026-10-27。**Status:** ready-for-agent。詞彙以 [CONTEXT.md](../CONTEXT.md) 為準（新增「子工作」「工時警示」）。承接 [工程師工作彙整規格](engineer-work-intake-spec.md) 中的「工程師進度頁」，不改變其資料模型與 [ADR 0004](adr/0004-single-workid-binding-with-auto-sync.md)。UI 原型見 `proto-types/engineer/a.html`（採用方案 A，已棄 B、C）。

## Problem Statement

課長在 `/weeks/<週>/<課>/engineer` 檢視工程師工作彙整時，頁面是一長串未分隔的清單：十位工程師、上百項多層工作捲動不盡，找不到特定工程師；工作編號只是純文字，要查工作細節得自己去另一個系統搜尋；每個工作旁都掛著常駐的 comment 輸入框，畫面雜亂；也看不出誰的工時不足或過量，得逐人加總。

## Solution

把頁面重排成「名冊＋總覽＋工作明細」：

- 左側固定名冊，點選工程師即捲動到其工作，並隨捲動標示目前位置。
- 主欄最上方是工具列與工時總覽表（工作時數、休假時數、主要耗時工作、工時警示），一眼看出誰的工時異常、誰在忙什麼。
- 工作明細逐層展開，工作編號是連到工作系統的連結。
- comment 預設收起，點 💬 才展開輸入；已有評語顯示成可點擊再編輯的引用條。
- 子工作（不論第幾層）與父工作一樣，可獨立標 ★ 與寫 comment。

## User Stories

1. 身為課長，我想在左側看到所有工程師的名冊，以便不必捲動就知道這週有哪些人。
2. 身為課長，我想點工程師姓名就捲動到該工程師的工作，以便快速定位。
3. 身為課長，我想名冊隨捲動標示我目前看到的工程師，以便不迷路。
4. 身為課長，我想名冊顯示每人工時與 ★ 數，以便掃一眼就知道誰標了重要工作。
5. 身為課長，我想名冊同時顯示有評語的工作數，以便知道我評論到哪。
6. 身為課長，我想名冊的 ★ 數與評語數包含所有層級的子工作，以便數字與畫面一致。
7. 身為課長，我想名冊維持彙整檔的順序，以便位置穩定、容易記憶。
8. 身為課長，我想在頁面最上方看到工時總覽表，以便先掌握全課狀況。
9. 身為課長，我想總覽表列出每人的工作時數與休假時數，以便對照出勤。
10. 身為課長，我想總覽表用「工作＋休假」對標準 40 小時，≤38 或 ≥44 時標示警示，以便發現工時不足或過量。
11. 身為課長，我想剛好 39 與 40 至 43 小時不被警示，以便警示只在真正偏離時出現。
12. 身為課長，我想總覽表有課別合計列，且合計列不套用工時警示，以便看全課總量而不被誤報。
13. 身為課長，我想總覽表列出每人耗時最多的前兩項頂層工作與時數，以便知道人力花在哪。
14. 身為課長，我想點主要耗時工作就跳到該工作的明細列，以便立刻看細節與寫評語。
15. 身為課長，我想總覽表可收合，以便不需要時讓出空間。
16. 身為課長，我想總覽表的姓名也能點擊跳轉，以便不只靠名冊。
17. 身為課長，我想每個工作編號都是連結，以便一鍵開啟工作系統的該筆工作。
18. 身為課長，我想編號連結在新分頁開啟，以便不離開週報頁。
19. 身為課長，我想工作系統的網址由設定決定，以便不同環境不改程式碼。
20. 身為課長，我想子工作逐層縮排顯示，以便看出父子關係。
21. 身為課長，我想最深三層的子工作都完整顯示，以便不漏看。
22. 身為課長，我想每個子工作各有自己的編號連結，以便直接開啟子工作。
23. 身為課長，我想子工作預設展開，以便不必多點一次就能評論。
24. 身為課長，我想用列左側的 chevron 個別收合工作，以便專注在某些分支。
25. 身為課長，我想全部展開或收合一次完成，以便快速整理畫面。
26. 身為課長，我想 comment 輸入框預設收起，點 💬 才展開，以便畫面乾淨。
27. 身為課長，我想展開後輸入框自動取得焦點，以便直接打字。
28. 身為課長，我想離開輸入框就自動儲存，以便不必再按儲存。
29. 身為課長，我想按 Esc 取消這次編輯，以便放棄誤輸入。
30. 身為課長，我想儲存後評語顯示成引用條，以便一眼看到內容。
31. 身為課長，我想點引用條就再展開編輯，以便修改既有評語。
32. 身為課長，我想有評語的 💬 按鈕呈現不同樣式，以便辨識哪些已評論。
33. 身為課長，我想子工作可獨立於父工作寫 comment，以便對不同層級給不同意見。
34. 身為課長，我想子工作可獨立標 ★，與父工作互不影響，以便只挑真正重要的那一層。
35. 身為課長，我想清空評語並離開輸入框就移除該評語，以便刪除不再需要的意見。
36. 身為課長，我想儲存失敗時看到頁首錯誤、畫面回到伺服器的實際內容，以便不誤以為已存。
37. 身為課長，我想「僅看重要」顯示自己重要或含重要子工作的工作，並連同祖先一起顯示，以便保留脈絡。
38. 身為課長，我想「僅看重要」隱藏沒標且沒有重要後代的兄弟工作，以便專注候選。
39. 身為課長，我想有上週評語的工作在評語區上方顯示一行灰字，以便延續判斷。
40. 身為課長，我想子工作各看自己工作編號的上週評語，以便對應正確。
41. 身為課長，我想「本週彙整未出現」的工作淡化並保留原有提示，以便知道它沒有新進度。
42. 身為課長，我想耗時與 RMS 標記沿用現有規則，以便行為不變。
43. 身為課長，我想上傳彙整檔的按鈕留在頁面工具列，且只有我（所屬課別課長）看得到，以便權限不變。
44. 身為課長，我想點名冊跳轉時網址的 hash 同步更新但不增加瀏覽器歷史，以便重新整理或分享後回到原位。
45. 身為課長，我想開啟帶 hash 的網址時自動捲到對應工程師或工作並閃爍提示，以便找到被分享的位置。
46. 身為部級主管，我想以唯讀方式檢視此頁，只看到 ★ 與評語文字，以便參考但不誤改。
47. 身為部級主管，我想唯讀時不出現 💬 與輸入框，評語引用條不可點擊，以便畫面不誘導編輯。
48. 身為別課課長，我想無法編輯他課的標註，以便權限邊界不變（沿用現有 403）。
49. 身為使用手機或窄螢幕的課長，我想名冊變成頂部橫向捲動的名字列，以便仍能跳轉。
50. 身為鍵盤使用者，我想所有按鈕與連結都有可見焦點，以便不靠滑鼠操作。
51. 身為偏好減少動態的使用者，我想捲動與閃爍提示在該設定下停用，以便不暈眩。
52. 身為課長，我想彙整檔尚未上傳時看到明確的空狀態，以便知道下一步是上傳。

## Implementation Decisions

- **範圍**：只改工程師進度頁的呈現與互動；後端標註 API 已支援任一層級工作（含子工作）獨立儲存重要旗標與 comment，不需修改。資料模型、合併、同步、綁定規則不變。
- **新增純函式模型模組**（工程師頁模型），集中放置有邊界值的規則，使 UI 元件保持薄層：
  - 工時警示：輸入工作時數與休假時數，回傳是否警示及方向（不足或過量）；標準 40，≤38 為不足、≥44 為過量。
  - 主要耗時工作：取一位工程師頂層工作中本週工時最大的前兩項，回傳編號、內容、時數；同時數時以彙整檔順序決勝。
  - 計數：遞迴計算某工程師所有層級的 ★ 數與有評語工作數。
  - 「僅重要」篩選：保留自己重要或含重要後代的工作，並保留其祖先；回傳篩選後的樹，不修改原資料。
  - 課別合計：加總各人工作時數與休假時數，不產生警示。
- **工時警示標準寫入領域詞彙**，常數為 40、−2、+4；警示僅出現在總覽表。
- **畫面結構**：左側名冊（sticky）、主欄由上而下為工具列、工時總覽、各工程師區塊；每位工程師區塊含標題（姓名、帳號、工時、休假、項數）與工作樹。
- **工作列**：每層一列，含 chevron（有子工作時）、★、編號連結、內容、耗時與 RMS 標記、狀態、進度、本週工時、💬。子工作依深度縮排；每層的 ★ 與 💬 作用於該列自己的工作編號。
- **評語互動狀態**：收起（無評語）→ 展開輸入（💬 或引用條觸發，自動聚焦）→ 失焦儲存；Esc 捨棄本次編輯；儲存後有內容顯示引用條、清空則移除。唯讀身分只顯示引用條。
- **儲存失敗**：沿用現有做法——重新載入以丟棄未儲存輸入，並於頁首顯示錯誤；樂觀更新只在成功後套用到本地資料。
- **上週評語**：沿用現有 `lastComment` 欄位，顯示在評語區上方的灰字，只在有值時出現。
- **工作編號連結**：網址樣板放入前端設定，預設為公司工作系統的 `BrowseWork.aspx?WorkID=<編號>`；以新分頁開啟並設定 `noopener`。連結樣板由設定取得，不寫死在元件。
- **導覽與 hash**：點名冊或總覽姓名時捲動並以 `replaceState` 寫入 hash（工程師為 `e-<帳號>`、工作為 `w<編號>`）；載入時解析 hash 並捲到目標後短暫標示。名冊目前位置由 IntersectionObserver 判定。
- **「全部展開／收合」與總覽收合**屬頁面本地狀態，不持久化。
- **窄螢幕**：名冊轉為頂部橫向列，其餘單欄；不另做專屬設計。
- **視覺**：沿用現有設計 token（steel／paper 色系、數字用 Bahnschrift、中文用微軟正黑）；不引入新字型或新色票，不使用動態效果，除跳轉後的短暫標示，且尊重減少動態設定。
- **權限**：編輯能力沿用現有「所屬課別課長」判定；上傳控制項與 💬 僅在可編輯時渲染。
- **既有元件拆分**：現有進度頁元件過大，改為「名冊、工時總覽、工程師區塊、工作列、評語編輯」等較小元件，對外屬性（週、檔案、可編輯、上傳事件）保持不變，使編輯器整合處不需改動。

## Testing Decisions

- **好測試的標準**：只驗證外部可見行為——畫面上看到什麼、儲存後重新載入是否仍在、規則邊界值的輸出；不測元件內部狀態、CSS 或私有函式。
- **縫 1（最高，沿用既有）：瀏覽器煙霧測試。** 擴充現有主流程：上傳彙整檔後，點名冊跳到某工程師並確認該區塊進入視野；在一個子工作上展開 💬、輸入、失焦儲存，重新載入後評語仍在，且父工作沒有該評語；子工作獨立標 ★ 後「僅看重要」顯示該子工作與其祖先；工時總覽出現預期的警示列；編號連結的 `href` 與 `target` 正確。
- **縫 2（新增，唯一的純函式縫）：工程師頁模型的單元測試。** 涵蓋工時警示邊界（38、39、40、43、44）、前兩項耗時工作與同時數決勝、計數含三層子工作、「僅重要」含祖先與兄弟隱藏、合計列不警示。
- **不新增後端縫**：子工作標註已有 HTTP 煙霧覆蓋，維持不變。
- **先例**：單元測試沿用既有的模型測試模式（甘特模型、工作綁定、專案進度）；煙霧測試沿用既有瀏覽器主流程的擴充方式，且依 [工程師工作彙整規格](engineer-work-intake-spec.md) 的原則只放一條主流程。
- **驗證指令**：於 `apps/web` 執行 `npm run check` 與 `npm run smoke`。

## Out of Scope

- 後端 API、資料模型、合併規則、綁定與同步邏輯的任何變更。
- 複製重要 ID、下載更新 JSON（已在工程師工作彙整規格中排除）。
- 評語自動帶入處級週報 `update_note` 之外的新用途；評語與重要旗標仍不出現在正式文件、不延續到下週。
- 名冊排序、搜尋、篩選工程師。
- 窄螢幕的專屬版面設計與觸控手勢。
- 工時警示標準可設定化（常數寫死，需變更時再改）。
- 工時警示的歷史趨勢、跨週比較。
- 展開、收合與工具列狀態的持久化。

## Further Notes

- 以 SEC1 範例資料（10 位工程師、112 筆互不重複的工作編號、最深三層）試算，工時警示會落在謝依真（32＋4＝36）與蔡焜來（36.5＋0.5＝37），其餘 39 至 43 小時不警示。
- 原型的狀態是假的（記憶體內），僅用來確認版面與互動；實作時評語與 ★ 走既有標註 API。
- 原型曾在子工作只畫一層純文字，造成子工作失去評語能力；實作時以遞迴工作列取代，避免重蹈。
- 工作系統網址沿用參考 HTML 中的網址；若各環境不同，部署時於設定覆寫。

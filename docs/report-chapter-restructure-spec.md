# 處會週報章節重排與維護系統別規格

狀態：草稿，2026-10-27。詞彙以 [CONTEXT.md](../CONTEXT.md) 為準（週報正式章節、系統異常、系統別、工作連結）。章節與系統別規則取代 [簡化週報解決方案規格](simplified-weekly-report-spec.md) 與舊票據中「每課一區」的正式版排版。

## Problem Statement

處會週報目前把內容依課別分成三大區，每區底下再放專案、重大系統異常、系統維護與營運、人力與組織異動、新技術評估。處級讀者要看的是「發生什麼事」，不是「哪課寫的」：同一系統的維護工作散在三課，要翻三處才能看全；章節名稱也偏長。

維護項目沒有系統別這一層，無法把同一系統的工作放在一起。另外正式版文件中，已綁定工程師工作的項目與關鍵任務沒有任何連結可點，要看工作內容只能到附錄表格找編號。

## Solution

正式版改為依章節彙整三課內容，不再有課別分區。章節依序為：管理摘要與待決策事項、專案、系統異常、維護、人力調整、新技術、附錄。

維護章節以系統別分組，三課相同系統別合併在同一標題下。課長在維護頁籤可新增系統別，並在組內新增項目或從工程師工作挑選。

正式版中已綁定工作的項目與關鍵任務，標題本身就是連結，點了以新分頁開啟工作系統該工作的頁面，不顯示工作編號。

## User Stories

1. 身為處級讀者，我想在正式版依章節閱讀，讓我不必逐課翻找同一類事項
2. 身為處級讀者，我想看到章節依序為專案、系統異常、維護、人力調整、新技術，讓我每週用同樣的順序閱讀
3. 身為處級讀者，我想看到管理摘要與待決策事項仍在文件最前方，讓我先掌握重點
4. 身為處級讀者，我想看到附錄仍在文件最後，讓我需要時查工程師工作明細
5. 身為處級讀者，我想讓某章節完全沒有內容時不出現標題，讓文件不留空白章節
6. 身為處級讀者，我想在專案章節看到所有課的專案放在一起，讓我一次掌握全部專案進度
7. 身為處級讀者，我想專案依課別一、二、三再依各課原順序排列，讓順序穩定可預期
8. 身為處級讀者，我想在系統異常章節依出現順序看到重大異常，讓我不用處理額外的分類
9. 身為處級讀者，我想在維護章節依系統別看到工作，讓同一系統的事項集中
10. 身為處級讀者，我想三課相同系統別的維護項目合併在同一個標題下，讓同一系統不被拆成多段
11. 身為處級讀者，我想系統別依第一次出現的順序排列、「未分類」排最後，讓沒有分類的項目不搶在前面
12. 身為處級讀者，我想在人力調整與新技術章節直接看到項目清單，讓這些少量內容不被多餘的層級打斷
13. 身為處級讀者，我想已綁定工作的項目與關鍵任務，其標題可以點，讓我能直接開啟工作頁面查看
14. 身為處級讀者，我想標題連結以新分頁開啟，讓我不會離開正在閱讀的週報
15. 身為處級讀者，我想連結的標題不顯示工作編號，讓版面保持乾淨
16. 身為處級讀者，我想沒有綁定工作的標題維持純文字，讓我知道哪些項目沒有對應工作
17. 身為處級讀者，我想附錄表格仍顯示工作編號並可點，讓我需要編號時仍可查
18. 身為處級讀者，我想非專案項目不標示是哪一課寫的，讓文件不因課別標籤變雜
19. 身為處級讀者，我想舊版正式版以相同規則顯示，讓我回頭看歷史版本時格式一致
20. 身為處級讀者，我想列印時章節與系統別標題不被切在頁尾，讓列印版好讀
21. 身為課長，我想編輯頁籤與正式版使用同一組章節名稱，讓我看到的名稱就是讀者看到的
22. 身為課長，我想仍只編輯自己課別的檔，讓權限與擁有權不因版面改變而改變
23. 身為課長，我想在維護頁籤新增系統別，讓我能為新出現的系統開一組
24. 身為課長，我想按「新增系統別」時輸入名稱，讓我命名清楚
25. 身為課長，我想新增系統別時同時產生一筆空白維護項目，讓空組存檔後不會消失
26. 身為課長，我想在每個系統別組內新增維護項目，讓新項目自動帶該組的系統別
27. 身為課長，我想維護頁籤依系統別分組顯示，讓我看得出正式版會怎麼分組
28. 身為課長，我想輸入系統別時看到本週三課已用過的名稱建議，讓我與其他課使用相同寫法而合併
29. 身為課長，我想系統別沒有固定清單，讓新系統不需要先請人維護清單
30. 身為課長，我想系統別比對只去除前後空白、其餘須完全相同，讓合併規則可預測
31. 身為課長，我想從頁籤頂端「從工程師工作挑選」挑出的維護項目進「未分類」，讓我之後再決定歸屬
32. 身為課長，我想在某系統別組內挑選工程師工作時，挑出的項目帶該組的系統別，讓我少一步操作
33. 身為課長，我想修改項目的系統別後，項目移到對應的組，讓我能更正分類
34. 身為課長，我想系統別沒有任何項目時該組消失，讓不用的組不會殘留
35. 身為課長，我想系統異常、人力調整、新技術頁籤維持平面清單，讓這些少量內容的編輯不變複雜
36. 身為課長，我想編輯畫面的甘特圖維持現狀，讓點任務名稱仍是選取任務
37. 身為課長，我想編輯畫面已綁定的任務仍顯示「已綁定 #編號」連結，讓我編輯時可查看工作
38. 身為部級主管，我想發布後的正式版採用新章節排版，讓處週會直接使用
39. 身為部級主管，我想既有未填系統別的維護項目歸入「未分類」，讓舊草稿不需要手動轉換就能發布
40. 身為部級主管，我想管理摘要與待決策事項的編輯與發布流程不受影響，讓我的作業不變

## Implementation Decisions

- **範圍**：只改處會週報正式版的呈現，以及維護頁籤的編輯。課檔、角色、發布、快照、版號、權限都不變；課長仍各自維護自己課檔。
- **章節與名稱**：專案（原進行中專案進度）、系統異常（原重大系統異常）、維護（原系統維護與營運）、人力調整（原人力與組織異動）、新技術（原新技術評估）。編輯頁籤與正式版共用同一組名稱。
- **彙整規則**：正式版把三個課檔的項目依章節彙整；某章節無任何項目時不顯示標題。
- **專案排序**：依課別（一、二、三）再依各課檔內原順序；不加課別標題。非專案項目不標示課別。
- **系統異常**：無下一層，依出現順序（一、二、三課的先後，各課檔內原順序）。
- **維護與系統別**：
  - 維護項目新增一個選填的系統別文字欄位；系統別不另存分組物件，也沒有固定清單。
  - 比對只去除前後空白，其餘須完全相同（含大小寫）；空白視為未填。
  - 正式版依系統別第一次出現順序分組（課別順序、課檔內順序），「未分類」固定最後；三課相同系統別合併。
  - 既有維護項目無此欄位，視為未分類；不遷移。
  - 人力調整、新技術暫無下一層。
- **編輯端維護頁籤**：
  - 依系統別分組顯示；每組有標題與「新增維護項目」；頁籤上方有「新增系統別」，輸入名稱。
  - 按「新增系統別」同時建立一筆帶該系統別的空白項目。
  - 系統別輸入欄提供本週三課已用名稱的建議；「未分類」組放最後。
  - 修改項目的系統別後項目移到對應的組；組內沒有任何項目時該組消失。
  - 組內「從工程師工作挑選」挑出的項目帶該組的系統別；頁籤頂端挑選則為未分類。
- **工作連結**：
  - 正式版正文中，已綁定工作的非專案項目標題與專案關鍵任務名稱本身是工作連結（新分頁開啟，沿用工作連結的網址設定），不顯示編號。階段與里程碑不能綁工作，不受影響。
  - 專案甘特圖中，已綁定任務的名稱在正式版文件模式下渲染為連結；編輯畫面的甘特圖維持點名稱即選取，不改。
  - 附錄表格不變，仍顯示並連結工作編號。
- **JSON 契約**：維護項目增加選填的系統別字串；其他欄位與檔案結構不變。無版本號變動與遷移。
- **發布快照**：快照仍是四個完整 JSON，章節彙整在讀取時進行；舊快照以同一規則顯示。
- **主要修改模組**（以職責描述）：章節名稱常數與資料型別；正式版頁面；新的章節彙整函式（輸入三個課檔，輸出章節與維護系統別分組，純函式）；檔案編輯頁籤（維護分組與挑選）；專案甘特圖元件（文件模式的名稱連結）；編輯導覽（頁籤名稱）。

## Testing Decisions

- **好測試的標準**：只驗證外部行為（給定三個課檔的內容，正式版或編輯頁籤呈現什麼順序、分組與連結），不驗證元件內部結構或私有函式。
- **接縫**：
  1. 純函式單元測試：新的章節彙整函式。這是最高的純邏輯接縫，涵蓋章節順序、專案課別排序、空章節省略、系統別合併與排序、未分類最後、空白與大小寫比對、舊資料無欄位。
  2. 瀏覽器煙霧測試（既有接縫）：正式版章節標題順序與不再有課別標題；已綁定項目與關鍵任務的標題連結（新分頁、無編號）；維護頁籤新增系統別、組內新增、組內挑選與頂端挑選的歸屬、修改系統別後移組。
- **先例**：`work-binding.test.mjs`、`engineer-model.test.mjs` 等以 `node --test` 直接載入 TS 的純函式測試；`browser-smoke.mjs` 內發布與正式版段落。
- **既有煙霧測試會受影響**：現有正式版斷言以 `[data-file="s1"]` 等課別區塊定位，需隨新排版調整；改寫時保持其他發布驗證意圖不變。
- **完成條件**：`npm run check` 與 `npm run smoke` 通過。

## Out of Scope

- 系統異常、人力調整、新技術的下一層分類（暫不需要，之後視需要再議）。
- 系統別固定清單、跨週的系統別管理或改名工具。
- 編輯端改為不分課；課長的擁有權與權限變動。
- 編輯畫面甘特圖名稱改成連結。
- 附錄內容與格式變更。
- 既有資料遷移（系統尚未發布，未填系統別一律視為未分類）。
- 列印版型的大幅調整（僅要求標題不被切在頁尾）。

## Further Notes

- 「處級週報」為口語說法，與「處會週報」是同一份文件。
- 決定不寫 ADR：章節排版與一個選填欄位容易回復。
- 同一系統若兩課用不同寫法（例如多一個空格以外的差異），不會合併；以輸入建議降低發生機率，不做模糊比對。

## Question

週報資料 repo 的結構與發布流程：

- 資料 repo 的目錄方式（每週一個資料夾，或每週一個檔案）。
- 課長的草稿如何交給部級：直接提交到資料 repo、還是另外交檔？
- 部級發布的動作：產生快照檔、提交、標記版本號。
- 前端如何找到最新發布版與歷史版本。

## Resolution

- **目錄（Q1）**：資料夾式。每週一個資料夾 `weeks/2026-W41/`，內含四個檔：課A、課B、課C 各一檔，加一檔 `cross.json`（跨課）。每位課長只改自己的課檔。
- **草稿提交（Q2）**：網站代為提交。課長在週報網站儲存時，網站以服務帳號把該課的 JSON commit 到資料 repo；課長不接觸 git。
- **發布快照（Q3）**：快照資料夾加 git tag。發布時複製四個完整 JSON 到 `publications/2026-W41/v1/`，版號每次發布遞增（v2、v3…），快照不可變；同時打 tag `pub/2026-W41-v1`，tag 只作索引。`weeks/` 草稿持續編輯；下週草稿從最新快照延續。
- **版本索引（Q4）**：`publications/index.json` 記錄每週每一版的週次、版號、發布時間、發布人與快照路徑。前端只讀此檔；「最新版」為最新週次中版號最高的一筆。只有發布動作會更新索引。

**Fog（未決，依賴部署方式）**：課長編輯時如何讀取 `weeks/` 下的目前草稿（後端讀 git 工作目錄，或前端讀靜態檔），已移入地圖的 Not yet specified，待部署方式定案後再問。

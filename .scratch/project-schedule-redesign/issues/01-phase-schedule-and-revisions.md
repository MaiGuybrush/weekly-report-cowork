# 01: 專案階段與完整修訂紀錄

**What to build:** 週報維護人可在專案中建立、排程、開始、完成、重開及更正專案階段，並讓授權讀者看見原始計畫、目前計畫、實際進度及每次修改的原因與前後值。以此建立三種時程項目共用的專案提交、修訂及權限行為。

**Blocked by:** None (can start immediately).

**Status:** done

- [x] 階段有預計起訖、實際起訖及開放、進行中、完成、取消的明確狀態；拒絕倒置日期及不符狀態的實際日期。可一次補登開始及完成日，完成後可有原因地更正日期或重開，且不會自動推定完成。
- [x] 首次輸入的計畫保存在建立紀錄；一般改期只改目前計畫。維護人可用明確的原始資料更正操作修正誤植，保留最初輸入、原因及前後值；偏差以有效原始計畫計算。
- [x] 建立後對日期、名稱、狀態及原始資料的每次修改都需非空白原因，產生不可覆寫的操作者、時間、動作、完整前後狀態修訂；授權讀者可查看歷史。未提交的私有時程草稿可捨棄，已建立項目不能硬刪除。
- [x] 每次寫入檢查專案項目的有效編輯租約與提交所依據的專案版本，並在同一交易更新時程、修訂及專案版本；版本過期時回傳最新專案時程，供編輯者處理衝突。
- [x] 以授權 HTTP 請求及暫存資料庫驗證提交、衝突與持久歷史；編輯畫面可輸入原因並檢視偏差和修訂。同步修正受此模型影響的設計及使用文件。

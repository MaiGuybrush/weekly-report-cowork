# 02: 關鍵任務與負責人

**What to build:** 週報維護人可把一項具體交付工作列為關鍵任務，指定負責人及計畫期間，放在一個專案階段或直接放在專案下，並明確確認進度與完成。

**Blocked by:** 01 — 專案階段與完整修訂紀錄。

**Status:** done

- [x] 關鍵任務必填名稱、負責人及有效預計起訖；負責人可為無本系統帳號的人或單位，指派本身不授予時程編輯權。
- [x] 可不選階段，或選同一專案的一個階段；拒絕跨專案歸屬。更改負責人、名稱或階段歸屬都需原因並留下完整修訂。
- [x] 開始、完成、補登實際起訖、更正及重開遵守與階段相同的明確狀態和日期規則；原始計畫、目前計畫及相對原始計畫的偏差均可查看。
- [x] 子任務全部完成不自動完成階段；維護人確認仍有未完成子任務的階段時看到警示，並須在確認原因中解釋例外。
- [x] API 與編輯畫面呈現任務及其階段關係，授權測試涵蓋無帳號負責人、跨專案拒絕、修訂及階段完成例外。

# UI 套用規格：週報網站全面採用原型視覺

## Problem Statement

週報網站（部級主管與三位課長使用）目前是單頁堆疊式編輯器：頁首各自為政、四個檔案（三課與跨課）在同一頁往下捲、沒有未儲存提示、正式版是卡片堆疊且看不出專案健康狀況。已有一份經過討論的拋棄式 HTML 原型，畫出了更好的資訊架構與視覺（頂欄、週次膠囊、左側 rail＋頁籤、固定儲存列、文件式正式版、帶偏差顯示的甘特圖）。使用者希望把原型的視覺與互動完整套用到現有 Angular 前端，同時不改後端、API 與 JSON 結構，並在過程中把過大的元件拆開。

## Solution

視覺全套採用原型，畫面與路由重組為：

- 所有頁面包在同一個外殼（頂欄：導覽、最近三週膠囊、姓名與角色標籤）。
- 首頁：最新正式版大卡片、週次清單（狀態膠囊）、依角色的「你可以…」說明。
- 週編輯：左側 rail 選檔（三課＋跨課）、頁籤選分項、固定儲存列顯示未儲存狀態，所有導覽狀態都在網址上。
- 正式版：單欄文件，順序為管理摘要、待決策事項、三課；專案標頭帶健康度膠囊。
- 原型沒畫但決定保留的資料（外部交付、證據連結、來源連結）有明確位置。
- 發布流程有確認、防誤發與版本下拉。

資料以元件內 view model 轉接，後端與 JSON 結構不動。拆元件採「先純拆、行為不變，再換視覺與路由」的順序。

## User Stories

外殼與導覽
1. 作為任一登入者，我想在每個頁面看到同一個頂欄，以便隨時知道自己在哪、是誰。
2. 作為任一登入者，我想在頂欄看到姓名與「課長／部級」標籤，以便確認自己的權限身分。
3. 作為任一登入者，我想在頂欄用最近三週膠囊切週，以便快速在本週與前兩週之間移動。
4. 作為任一登入者，我想切週時保留目前的課別與頁籤（若網址帶有），以便比較不同週的同一處內容。
5. 作為任一登入者，我想用頂欄的「首頁／編輯／正式版」導覽，以便不必靠「返回」連結找路。
6. 作為任一登入者，我想「編輯」直接帶我到最新週，以便馬上開始工作。
7. 作為任一登入者，我想「正式版」直接帶我到最新正式版，以便立刻閱讀。
8. 作為任一登入者，我想在尚無任何正式版時看不到「正式版」導覽，以便不會點進空頁。
9. 作為任一登入者，我想複製網址給同事就能開到同一課、同一頁籤，以便溝通時指向確切位置。

首頁
10. 作為任一登入者，我想在首頁看到最新正式版大卡片（週次、版號、發布日），以便一鍵閱讀。
11. 作為任一登入者，我想在尚無正式版時看到「尚無正式版」的卡片，以便知道是空狀態而非壞掉。
12. 作為任一登入者，我想在週次清單看到每週的狀態膠囊（「已發布 vN」或「草稿」），以便知道每週進度。
13. 作為任一登入者，我想點週次進入該週編輯，以便從首頁開始工作。
14. 作為課長，我想在首頁看到「你可以…」說明（編輯本課專案與分項、其他課與跨課唯讀），以便清楚我的權限邊界。
15. 作為部級主管，我想在首頁看到「編輯管理摘要與待決策事項、發布、建立下週」說明與「建立下週」按鈕，以便一站完成週期操作。
16. 作為部級主管，我想建立下週時沿用既有行為（由最新正式版複製，下週已存在則不覆蓋），以便不改變我的作業習慣。

週編輯：rail 與頁籤
17. 作為課長，我想進入週編輯時預設看到自己那一課，以便少點一次。
18. 作為部級主管，我想進入週編輯時預設看到跨課，以便直接編輯我負責的內容。
19. 作為任一登入者，我想用 rail 在三課與跨課之間切換，以便一次只面對一份內容。
20. 作為任一登入者，我想在 rail 看到哪些檔有未儲存的變更（髒點），以便不遺漏。
21. 作為任一登入者，我想在 rail 看到哪些檔對我是「唯讀」，以便不必試著輸入才發現不能改。
22. 作為任一登入者，我想用頁籤切換專案、系統維護、人力異動、新技術等分項，以便專注於單一分項。
23. 作為任一登入者，我想頁籤上帶有項目數，以便一眼看出哪些分項有內容。
24. 作為任一登入者，我想用鍵盤在 rail 與頁籤間移動，以便不依賴滑鼠。
25. 作為任一登入者，我想直接開啟含課別與頁籤的深連結，以便從書籤或訊息跳到定位。
26. 作為任一登入者，我想路由指向不存在的週或課別時被帶回首頁並看到「找不到該週」提示，以便不卡在空白頁。

唯讀與權限
27. 作為課長，我想只能編輯自己課別的內容，以便避免誤改他課。
28. 作為課長，我想看他課與跨課時為唯讀並看到 🔒 說明，以便知道原因。
29. 作為部級主管，我想只能編輯跨課，其餘三課唯讀，以便維持職責分離。
30. 作為任一登入者，我想權限不足的路由顯示置中的無權限卡片，以便得到明確回應。
31. 作為任一登入者，我想登入過期時行為與現在相同（重新驗證），以便這次改版不改變登入流程。

未儲存狀態與離開保護
32. 作為編輯者，我想在修改後立刻看到固定儲存列顯示「● 有未儲存變更」，以便知道需要存檔。
33. 作為編輯者，我想儲存後髒點與提示消失，以便確認存檔成功。
34. 作為編輯者，我想換課或換頁籤時不被打斷，以便在同一份草稿中自由查看。
35. 作為編輯者，我想換週、離開編輯畫面或關閉分頁時，若仍有未儲存變更就被提示，以便不意外遺失內容。
36. 作為編輯者，我想離開提示可用 Esc 取消，以便用鍵盤也能操作。
37. 作為編輯者，我想儲存失敗時錯誤訊息出現在固定儲存列、髒點與草稿都保留，以便修正後重試而不丟內容。
38. 作為編輯者，我想儲存成功才出現 toast，以便不被成功訊息以外的雜訊打擾。
39. 作為編輯者，我想內容載入中時看到「載入中…」且頂欄與 rail 已先出現，以便知道頁面沒當掉。

專案區塊與甘特圖
40. 作為課長，我想每個專案標頭有標題、負責人、參與課別與健康度膠囊，以便一眼掌握專案概況。
41. 作為任一閱讀者，我想健康度膠囊顯示「依計畫／逾期 N 項／曾延後 N 項／完成 x/y」，以便不必逐項查日期。
42. 作為任一閱讀者，我想編輯頁與正式版的健康度一致，以便數字對得起來。
43. 作為任一閱讀者，我想甘特圖同時看到計畫條與實際條，以便比較偏差。
44. 作為任一閱讀者，我想實際已逾計畫結束日的條為紅色，以便醒目看出逾期。
45. 作為任一閱讀者，我想進行中的實際條有條紋，以便與已完成區分。
46. 作為任一閱讀者，我想看到今日線與其日期標籤，以便判斷目前進度位置。
47. 作為任一閱讀者，我想已取消項目以淡化與刪除線顯示，以便保留歷史又不干擾判讀。
48. 作為任一閱讀者，我想將滑鼠停在甘特列上看到計畫、實際與偏差說明（原生 tooltip），以便取得精確日期。
49. 作為課長，我想在「時程明細」摺疊區編輯階段、關鍵任務、里程碑與四個日期，以便維護時程。
50. 作為課長，我想計畫結束早於開始時看到明確錯誤，且有錯的專案被標示，以便修正後才儲存。
51. 作為課長，我想新增專案時有空狀態引導，以便知道從哪開始。

保留資料的位置
52. 作為課長，我想在時程明細之下的第二個摺疊區「外部交付（N 項）」維護外部交付（內容、供應者、到期日、狀態、關聯時程項目），以便追蹤外部依賴。
53. 作為正式版閱讀者，我想在甘特圖下方看到外部交付唯讀簡表，以便知道專案卡在誰手上。
54. 作為課長，我想在關鍵任務列尾用「📎 N」展開面板，連結或移除證據工單、挑選候選工單、手動輸入 workId，以便為進度佐證。
55. 作為任一閱讀者，我想在甘特圖與正式版的任務上看到 📎 數量，並可在 title 看到摘要，以便知道有佐證。
56. 作為課長，我想在每個非專案分項項目卡片底部新增、編輯、移除來源連結（標籤與網址），以便附上參考資料。
57. 作為正式版閱讀者，我想項目下方的來源連結為可點連結，以便跳去查證。

分項內容
58. 作為課長，我想系統維護與新技術項目有標題與內容欄位，以便記錄。
59. 作為課長，我想人力異動項目有職責或交接、生效日期、工作影響、下一步欄位，以便完整交代。
60. 作為正式版閱讀者，我想人事項目顯示「交接／影響／下一步（生效日）」行，以便不漏看影響。
61. 作為部級主管，我想在跨課編輯管理摘要與待決策事項（說明、決議結果、新到期日），以便傳達重點。
62. 作為任一閱讀者，我想空的分項或課別在正式版略過標題，以便文件精簡。
63. 作為任一閱讀者，我想編輯頁空分項顯示虛線框空狀態與說明，以便知道是尚未填而不是壞掉。

發布與版本
64. 作為部級主管，我想在固定儲存列看到「發布 {週}」，以便在同一個位置完成存檔與發布。
65. 作為部級主管，我想按下發布先看到確認對話框（「發布 2026-W42 為 v3？發布後無法修改」），以便避免誤發。
66. 作為部級主管，我想跨課檔仍有未儲存變更時發布鈕停用並提示「請先儲存」，以便不會漏發畫面上的修改。
67. 作為部級主管，我想按下發布後按鈕顯示「發布中…」並停用，以便避免連點產生重複版本。
68. 作為部級主管，我想發布成功直接進入剛發布的正式版，以便立刻確認結果。
69. 作為部級主管，我想發布失敗時留在編輯頁並在儲存列看到原因，以便處理後重試。
70. 作為正式版閱讀者，我想在標題列用版本下拉切換，且依週分組、新到舊排列、標籤為「v3 · 10/09 發布」，以便找到歷史版本。
71. 作為正式版閱讀者，我想檢視非最新版時標題列旁有「舊版」膠囊，以便不誤把舊版當現況。
72. 作為正式版閱讀者，我想標題列有列印鈕，以便直接輸出。

正式版文件與列印
73. 作為正式版閱讀者，我想文件順序為管理摘要、待決策事項、三課，以便先讀重點。
74. 作為正式版閱讀者，我想標題列顯示「週次 · vN」，以便確定所讀版本。
75. 作為正式版閱讀者，我想列印時健康度膠囊與甘特條紋仍可辨識，以便紙本一樣好讀。
76. 作為正式版閱讀者，我想列印時隱藏頂欄與操作鈕，以便只輸出內容。

可及性與環境
77. 作為鍵盤使用者，我想可見的 focus 外框與按 Tab 能抵達儲存鈕，以便不用滑鼠完成存檔。
78. 作為輔助科技使用者，我想 rail 與頁籤具備 tab 語意與目前選取狀態，以便被正確朗讀。
79. 作為輔助科技使用者，我想髒點有「有未儲存變更」的名稱、錯誤訊息為 alert、載入為 status，以便得到狀態通知。
80. 作為偏好減少動態的使用者，我想動畫遵循系統設定，以便不暈眩。
81. 作為窄螢幕使用者，我想在 860px 以下仍無橫向捲軸且 rail 可用，以便在小視窗也能工作。

驗收與維護
82. 作為維護者，我想健康度與髒狀態比對是有單元測試的純函式，以便日後調整規則有保護網。
83. 作為維護者，我想元件依 Shell／Home／WeekEditor／FileView／CrossEditor／ProjectHeader／ProjectSchedule／Gantt 切開，以便改一處不牽動全部。
84. 作為維護者，我想全部樣式集中在全域樣式並使用原型 token，以便日後調色只改一處。
85. 作為維護者，我想改版後 `data-*` 測試契約不被破壞並新增必要屬性，以便煙霧測試穩定。

## Implementation Decisions

**資料（不動後端與 JSON）**
- 原型多出的功能（待決策事項、交接／影響／下一步、管理摘要、參與課別）在現有型別已存在，差異只在命名與結構：管理摘要對應 `managementSummary`、待決策對應 `pendingDecisions`、原型的專案／分項在現有資料中同為 item，專案是 `section: "projects"` 的 item。以元件內 view model 轉換，不新增欄位。
- 保留顯示：外部交付、證據連結、來源連結。捨棄顯示（資料照留）：前次承諾、單項待決策。待決策只存在於跨課清單，由部級維護。
- 缺口：無。若實作中發現需新欄位，停手回報，屬 `weekly-report-simplified` 範圍。

**外殼與路由**
- 新增 Shell 為 layout route，包住所有頁面與路由輸出；各頁自帶 header 與「返回」連結移除。無權限頁與啟動錯誤頁不含 Shell，只套原型 token 的置中卡片。
- 編輯路由為 `weeks/:week/:file/:tab`。缺省時課長導向自己的課、部級導向跨課。不存在的週或課別導回首頁並 toast「找不到該週」。
- 頂欄「編輯」→ 最新週；「正式版」→ 最新正式版，無則隱藏。切週保留課別與頁籤。
- 首頁狀態僅由發布索引推得：有已發布版本顯示「已發布 vN」，否則「草稿」。不做「已儲存 2/3」與逾期項目數（API 無資料）。
- 預覽正式版不做。

**元件邊界（每元件一檔）**
- `Shell`、`Home`、`WeekEditor`（rail、路由、固定儲存列、髒狀態、發布）、`FileView`（單課頁籤與各區段表單）、`CrossEditor`、`ProjectHeader`（編輯頁與正式版共用）、`ProjectSchedule`、`Gantt`。`App` 只留根元件。
- 健康度為獨立純函式模組，與甘特模型並列，今天以瀏覽器日期為準。編輯頁與正式版共用。
- 髒狀態＝草稿與已儲存快照比對，粒度為「某檔有沒有髒」，不做「N 處」計數。換週、離開畫面使用路由離開守衛，關閉分頁使用 `beforeunload`；換課、換頁籤不擋。

**樣式**
- 整檔改寫為原型 token（色票與數字／文字兩種字型），舊規則刪除，不用元件內樣式。
- 甘特補逾期紅與進行中條紋（由甘特模型依計畫結束日對今天判斷，輸出純樣式 class），今日標籤膠囊套樣式。Tooltip 保留原生 title，浮動 tooltip 不做。
- 僅採原型 860px 斷點；列印只支援正式版（原型規則加現有邊距，兩段舊列印規則合併）。

**畫面行為**
- 唯讀規則沿用 `canEdit`：課長編自己的課、部級編跨課，其餘唯讀並顯示 🔒 說明；rail 標「唯讀」。
- 載入中：內容區「載入中…」(`role="status"`)，頂欄與 rail 先渲染。
- 儲存或發布失敗：固定儲存列內顯示 (`role="alert"`)，持續到下次儲存或編輯，草稿與髒點保留；時程錯誤同位置並標示有錯專案。成功才用 toast。
- 空狀態：統一虛線框；有權限者顯示「新增專案」；首頁無正式版顯示「尚無正式版」；正式版中無內容的課略過標題。
- 正式版：單欄文件，標題列含「週次 · vN」、版本下拉、列印鈕；專案標頭含標題、負責人、參與課別、健康度膠囊；人事項目補「交接／影響／下一步（生效日）」行。

**保留資料的位置**
- 外部交付：專案區塊在「時程明細」摺疊區之下新增第二個摺疊區「外部交付（N 項）」，表格列編輯；正式版甘特下方為唯讀簡表（內容、供應者、到期日、狀態）。
- 證據連結：僅關鍵任務、可編輯時，明細列尾「📎 N」按鈕展開面板（已連結＋摘要、候選工單挑選、手動 workId）；甘特保留 📎 chip；正式版任務列尾顯示「📎 N」，title 帶摘要。
- 來源連結：每個非專案分項項目卡片底部新增編輯列表（標籤、網址、移除、新增）；正式版項目下方顯示為可點連結。屬新增 UI，資料結構不變。

**發布流程**
- 按「發布 {週}」先顯示原生 `<dialog>` 確認；停用條件為部級自己的跨課檔為髒狀態；各課無資料不擋；按下後顯示「發布中…」並停用；成功導向剛發布的正式版；失敗顯示於儲存列。
- 版本下拉依週用 `<optgroup>` 分組，週次與組內版本皆新到舊，標籤「v3 · 10/09 發布」，預設選網址指定版本；首頁最新版沿用既有最新版判斷。檢視非最新版時標題列旁加灰色小膠囊「舊版」，不做橫幅。

**可及性**
- 以原型的 `:focus-visible`、`prefers-reduced-motion`、`aria-label` 為基準；rail 與頁籤使用 `role="tablist"`／`"tab"` 與 `aria-current`／`aria-selected`；髒點 `aria-label="有未儲存變更"`；離開提示可 Esc。不做完整 WCAG 稽核。

**實作順序（供切票）**
1. 純拆元件，行為不變，現有測試綠燈即驗收。
2. 全域樣式換 token，甘特補逾期與條紋。
3. Shell、路由、首頁。
4. 週編輯 rail／頁籤／儲存列／髒狀態／離開保護。
5. 專案標頭、健康度、保留資料位置、人事欄位。
6. 正式版文件、發布流程、版本下拉、列印。
7. 非原型狀態（載入、失敗、空狀態）與可及性補強；改寫煙霧測試貫穿各步驟。

## Testing Decisions

- 好的測試只驗外部可見行為（畫面文字、數量、可用與否、網址、權限結果），不驗內部元件結構或 CSS class（既有甘特斷言除外）。
- **主縫：改寫後的瀏覽器煙霧測試**（Playwright，對真實 API＋mock UAC）。直接改寫既有檔，不另開新檔。角色維持兩個：一位課長（第一課）與部級；課長視角順帶驗跨課唯讀與他課 rail 標唯讀。第二、三課權限隔離由 API 層 HTTP 測試覆蓋，不重複。身分由 token 決定；原型角色切換列不移植。
- 時間固定為 2026-10-12（與原型一致）；fixtures 至少含一個逾期項與一個曾延後項。
- 測試契約：現有 `data-*` 全部保留；新元素補同風格屬性：`data-shell`、`data-rail-file`、`data-tab`、`data-dirty`、`data-health`、`data-week-status`，發布與確認對話框依需要補同風格屬性。
- 既有編輯／儲存／發布／版本切換流程之外，新增覆蓋：(1) 深連結直接開對應頁籤；(2) 改動後出現髒點與「● 有未儲存變更」，儲存後消失；(3) 髒狀態下換週跳離開提示；(4) 首頁週次狀態膠囊；(5) 正式版專案標頭健康度文字。另補：跨課檔髒時發布鈕停用、發布確認對話框、版本下拉分組與「舊版」膠囊、外部交付／📎／來源連結的編輯與正式版呈現、Tab 能到儲存鈕。
- 不做像素比對；每個畫面另存一張截圖當 artifact，不作通過條件。
- **輔縫：純函式單元測試**，沿用既有 `tests/*.test.mjs` 風格：健康度（依計畫／逾期／曾延後／完成 x/y）、髒狀態快照比對。
- 「綠燈」＝既有單元測試、API HTTP 煙霧測試、改寫後瀏覽器煙霧測試全數通過。窄螢幕只手動看一次，不列入自動化。

## Out of Scope

- 後端、API、JSON 結構變更（屬 `weekly-report-simplified` 範圍）。
- 發布前「預覽正式版」（草稿渲染來源與路由）。
- 首頁「已儲存 2/3」、逾期項目數（API 無資料）。
- 浮動 tooltip、骨架屏、完整 WCAG 稽核、手機專屬設計、編輯頁列印。
- 像素比對與視覺回歸。
- 發布前檢查各課是否有資料。
